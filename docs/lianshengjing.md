# 练声镜：进度与后续计划

这份文档记录这个分支（练声镜）做到了哪里、怎么构建和发布、已知的限制，以及接下来要做什么。
接手的人（或模型）先读这一份。最后更新：2026-11-22（音准标签复测、交互整理之后）。

- 线上地址：<https://terminaterfxy.github.io/lianshengjing/>（完整版合成器在后面加 `?full`）
- 仓库：<https://github.com/terminaterfxy/lianshengjing>（`main` 是源码，`gh-pages` 是发布的网页）
- 原项目：[jamesondh/chimera-vocal-synth](https://github.com/jamesondh/chimera-vocal-synth)（MIT），本分支从 `caf270a` 分出

## 它是什么

用户的妻子在学唱歌，主要困难是“找不到发声位置，和气息有关；有时找到了，下次又忘了”。
练声镜让她对着手机唱，从声音里读出口型、声带闭合和气息，并能把“唱对的那一次”记为参考，以后照着找。

所有读数都是**从声音推算的估计值**，不是对喉咙的测量。最可靠的用法是“同一个音、同一个字、相近的音量，和自己上次比”。

## 已经做好的

页面分四个标签（音准 · 气息 · 声带 · 口型），底部固定“开始听 / 停止”和“记为参考”。
每个标签只放自己那类读数，不要把功能堆到一页（用户明确要求过）。

| 标签 | 内容 | 代码 |
|---|---|---|
| 音准 | 音名和偏差（音分）、最近 10 秒音高曲线、这个音的摆动 / 走势 / 颤音 | `src/mic/pitch.ts` |
| 气息 | 这口气的时长、音量曲线、音量起伏、走势、起音方式；历史记录（每天最长的一口气、最近几次） | `src/mic/breath.ts` `history.ts` |
| 声带 | 闭合读数（每个周期合拢的时间占比）、声带动画、声带拉长、录音域 | `src/mic/glottis.ts` `range.ts` |
| 口型 | 头部剖面图跟着声音动、气道图、校准（唱啊/衣/乌）、可选的气流模拟 | `src/mic/formants.ts` `calibrate.ts` `track.ts` |

- 页面：`src/ui/components/MicPage.tsx`；每帧的读数逻辑都在 `src/mic/session.ts`（不依赖浏览器，可回放测试）。
- 全界面中文：`src/ui/zh.ts`（显示时翻译，组件里仍是英文；地址加 `&lang=en` 看英文）。
- 离线与主屏幕图标：`public/sw.js`、`public/manifest.webmanifest`。
- 存在手机本地的数据（按网址分开）：校准、音域、参考、气息历史（`chimera.mic.breaths`）、上次所在的标签、气流模拟开关。
  参考（`chimera.mic.closureRef`）里存：闭合、音高、音量、音量起伏、起音，以及音准页的音（MIDI）、摆动、颤音。
  哼唱（读不出元音、没有闭合）也能记，这时只记音准和气息；各页显示的参考音名一律用音准页的音名。

### 交互上的约定

- 打开默认在音准页；上次停在哪个标签，下次就回到哪个。
- 底部一行：出错或刚点过按钮时显示那句话（3 秒）；口型页显示实测共振峰；其他页只说“正在听… / 正在听 / 听到辅音或气声”。
- 音名有迟滞：中心离开当前音名超过 0.6 个半音立刻换；在 0.5–0.6 之间要停够 0.25 秒才换。
  这样颤音跨过两个音名的交界时不会来回跳，开头那一下认错了也会很快改过来。声带、口型页的音名用同一个。
- “这个音”在声音停下后改叫“上一个长音”，停止听之后也留着；“记为参考”在声音停下后 4 秒内仍可点。
- 停止听时指针、闭合标记都收起，不会停在最后一个读数上。

### 准度（都是在引擎生成的声音上测的）

- **元音校准**：一种嗓音套另一种体型的模型，10 个元音认对的个数从 2–3 个升到 8–9 个。
- **声带闭合**：约 1.6 万段已知真值的声音，每段随机加混响、噪声、麦克风频响偏差、44.1/48 kHz。
  平均误差约 4 个点。混响、噪声、采样率几乎不影响；**唱的力度**会：轻声偏紧 3–4 点，大声偏松 3–4 点；嗓音很粗糙时偏松约 3 点。
  同力度下比较两次（真实差 ≥ 6 点）正确率 97–98%，不同力度 94–96%。单独的“漏气缝隙”估不出来。
- **起音**（软 / 硬 / 气）：引擎的直接起、声门塞音起、带 h 起，在安静、噪声、两种混响下，60/30/15 帧，144 次全对。
- **气息**：一口气从出声算到安静满 1 秒；带歌词的句子不会被辅音切断。颤音的脉动已滤掉。
- **音域**：滑音或逐个唱都能记，A3–A5 的音阶误差在四分之一个半音内。
- **音准**：音高精确已知的合成歌声，每秒 60 / 30 / 20 帧：音名全对，偏差误差 ≤ 1 音分（A3–A5）；
  颤音 4.5–7.5 次/秒、±25–90 音分，速度误差 < 0.05 次/秒，幅度误差 ≤ 5%；40 音分的下滑读出 36 / 36.5；
  连唱音阶每个音都认对。引擎唱的长音（自带几音分的漂移）偏差 ≤ 2 音分，颤音 6.0 次/秒、幅度误差 ≤ 6%。
  带歌词的《送别》两句：显示的每个音都是旋律里有的。帧时快时慢（模拟手机卡顿）时摆动 ≤ ±1 音分。
  每秒不到 12 帧时不给“这个音”的读数（颤音会和帧率混叠，读出来全错）。
  很重的气声、带混响和噪声的房间、24 kHz 和 16 kHz 的麦克风（蓝牙耳机）：偏差误差 ≤ 4 音分，颤音幅度误差 ≤ 12%。
  15 秒的长音时长读 15.0 秒。
- **采样率**：分析帧按时长取（约 46 毫秒，`frameLength()`），不按采样点数。以前固定 2048 点，16 kHz 时帧长变成 128 毫秒，
  颤音被抹平、幅度少读三分之一到一半，闭合也更差。改后闭合在 16 kHz 下平均误差女声 6.2、男声 4.4 个点。
- 自测 `tools/mic-selftest.ts` 共 60 项，全部通过。

### 已知限制

- 真人嗓音和 iPhone 麦克风上的准度**没有系统验证过**，只有用户夫妇的试用反馈。
- 口型：鼻音 m/n/ng、爆破音、约 A4 以上的高音认不准；辅音只分 s 类、sh/x 类、h/f 类，引擎的 h 会被读成 s。
- 声带拉长是按音高换算的，不是量出来的；同一音高真声假声显示不出区别。
- “松 / 适中 / 紧”“很稳 / 较稳”的分界是经验值，应以她自己的参考为准。音准页的“准 ±10 / 略偏 ±25 音分”
  “摆动 ±6 很稳 / ±15 较稳”“走势差 10 音分才提示”“颤音 4.5–7.5 次/秒为常见范围”也是经验值。
- 音准：程序不知道她想唱哪个音，只和最近的半音比（A4 = 440 Hz 十二平均律），偏差过 50 音分会认成旁边的音；
  音高检测上限约 A5（880 Hz，检测范围 70–900 Hz）。两个都很短（不到约 0.4 秒）的相邻音可能分不开，
  这时不显示那个音，而是保留上一个读得出的音。超过 12 秒的长音，时长照算，但摆动、走势只按最后 12 秒算。

## 怎么构建、自测、发布

这台机器上**没有 bun**，用 node + npm 代替；Rust 是用 Homebrew 的 rustup 装的。

```bash
export PATH="/opt/homebrew/opt/rustup/bin:$PATH"

# 引擎改了才需要（wasm）
cargo build -p chimera-wasm --release --target wasm32-unknown-unknown
cp target/wasm32-unknown-unknown/release/chimera_wasm.wasm src/wasm/chimera.wasm

# 自测要用到的两个本地工具
cargo build --release -p chimera-cli
cargo build --release -p chimera --example glottis_sweep

npx tsc --noEmit                      # 类型检查
node tools/mic-selftest.ts            # 自测，约两分钟，临时文件自己删
CHIMERA_BASE=/lianshengjing/ npx vite build   # 发布用的构建（带子路径）
```

发布：把 `dist/` 里除 `plugin/`、`install.sh`、`shows/`、`*.map` 以外的内容，加上 `LICENSE` 和 `.nojekyll`，
作为一次提交强推到 `gh-pages` 分支。源码推 `main`（本地分支名是 `lsj`，推送用 `git push lsj lsj:main`）。

本地给手机试用：上一级目录的 `serve.mjs`（HTTPS 8443，自签证书），由 `.claude/launch.json` 的 `lianshengjing` 启动；
它把站点放在 `/lianshengjing/` 下，和线上一致。

### 这台机器的注意事项

- 项目在 iCloud 同步的桌面里，磁盘只剩约 9 GB。项目文件夹叫 `chimera.nosync`（不参与同步），`chimera` 是指向它的链接；
  `target`、`node_modules`、`dist` 也各是指向 `*.nosync` 的链接。**不要把它们改回普通文件夹**，否则 iCloud 会把文件挪到云端。
- 测试数据放在系统临时目录，**算完一批删一批**；曾经一次写满 1.2 GB 触发了存储报警。
- 内置浏览器面板在后台时只有每秒几帧，不能用来验证需要连续帧的读数；这类逻辑用 `session.ts` 的 `replay()` 在 node 里按 60 帧回放。
  面板隐藏时干脆没有动画帧（页面显示“画面 0 帧/秒”）；要在页面里点着测，可以只在测试页里临时把 `requestAnimationFrame`
  换成 MessageChannel 驱动的约 60 帧，再用 `getUserMedia` 返回一个 AudioContext 造的假声音。
- iPhone 上音频必须在点击的那一下里创建（`MicListener.start`），否则会一直暂停。

## 接下来要做的

用户的妻子想要：音准、气息稳定度、一口气的长度、明亮度/共鸣、换声区，最好加上节奏。
其中气息稳定度和一口气的长度已经有了。已和用户确认过评估，按下面的顺序做，**每做完一项就发布一次**
（用量额度用完时任务会被突然中断，不要攒着一起发）。

1. ~~音准（新标签）~~：**已完成**（2026-11-22，提交 `f3509e4`，已发布）。
2. ~~气息的历史记录~~：**已完成**（2026-11-22）。一口气（出声到安静满 1 秒）唱满 2 秒就记下时长、音量起伏、走势；
   正唱着点“停止”也记。气息页下面是今天 / 最好成绩、每天最长一口气的柱状图、最近 5 次，清除要连点两次。最多存 2000 条。
3. **音色（新标签）：明亮度**：3 kHz 附近（歌手共鸣峰）的能量占比。受元音、麦克风频响、距离影响，只适合和自己比。
   做法同闭合：用引擎造已知答案的声音来检验（引擎有 brightness 和 epilarynx 参数），再定读数。
   “共鸣在头腔还是胸腔”这种体感量不出来，要在页面上说清楚。
4. **节奏（单独的练习入口）**：节拍器 + 检测每个字的起点，报告抢拍或拖拍多少毫秒。
   注意：节拍声会被麦克风收进去，需要耳机或只用屏幕闪烁；蓝牙耳机有 0.1–0.25 秒延迟，必须先做延迟校准；连唱的元音起点难定。
5. **换声区（放在声带标签，标“实验性”）**：让她从低到高滑一次音，把闭合、音量、明亮度沿音高画出来，在突变处标出换声点。
   把握最小：闭合读数有约 4 点误差且受力度影响，引擎也不太会模拟真假声转换，没法造真值验证。先看前几项在她嗓子上的表现再决定做不做。

做完后的标签分组：**音准 · 气息 · 声带 · 音色 · 口型**，节奏单独一个入口（音色标签插在声带和口型之间）。

### 做过又放弃的方向（不要重做）

- 让引擎先唱一遍做示范：合成声音太机械，用户听后明确放弃。
- 用前置摄像头看嘴型：用户否决（不是所有音都要张大嘴）。
- 靠语音识别认全部辅音、按歌词跟随显示标准口型：评估后认为唱歌时用不上，没做。
- 用更复杂的模型消除力度对闭合读数的影响：试过，声音里不带这个信息；改为记参考时记音量，力度差得多时页面提醒。
